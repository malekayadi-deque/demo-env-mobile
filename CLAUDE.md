## Project Overview

An e-commerce demo Android app (Kotlin + Jetpack Compose) integrated with **axe DevTools** by Deque for automated accessibility testing. The primary purpose of this repo is to demonstrate axe DevTools accessibility scanning on each screen of the app.

## Architecture

MVVM + Repository. All product/catalog data is **static local data** (no network API) — `ProductRepository` reads directly from in-memory lists in `data/local/ProductData.kt`. Cart and Wishlist state is persisted via DataStore.

Key directories under `app/src/main/java/com/embel/shop/`:

```
data/
  local/          → static in-memory data (ProductData, BannerData, etc.)
  model/          → data classes
  repository/     → ProductRepository (static), CartRepository, WishlistRepository
  datastore/      → DataStore wrappers for cart, wishlist, preferences
di/               → Hilt AppModule (singleton providers)
navigation/
  Screen.kt       → sealed class with all route strings
  EmbelNavGraph.kt → NavHost wiring all composables
ui/
  components/
    common/       → shared components (EmbelBottomBar, EmbelTopAppBar, CartDrawer, etc.)
    filter/       → filter panel components
    product/      → product detail components
  screens/        → one directory per screen
  theme/          → Material 3 theme (Color, Type, Shape, Dimens)
viewmodel/
  UIStateViewModel.kt → shared overlay state: cart drawer, search popup, filter panel, quick view, cookie consent
  CartViewModel, ShopViewModel, ProductDetailViewModel, etc.
```

### Navigation notes

- `MainActivity` renders `EmbelNavGraph` directly — no bottom nav in `MainActivity`.
- `EmbelBottomBar` lives inside each individual screen's `Scaffold`.
- `ProductDetailScreen` accepts a `variant` parameter (`"onsale"`, `"grouped"`, `"external"`, `"outofstock"`) to vary its presentation; all four variants share the same composable.
- `UIStateViewModel` is the single source of truth for transient overlay state shared across screens (cart drawer open/close, search, filter, quick view dialog, cookie banner).

## Credentials & local.properties

**All secrets live in `local.properties` (git-ignored).** This file must contain four keys for the project to build and tests to run:

```properties
# Android SDK path (auto-generated by Android Studio)
sdk.dir=/Users/<you>/Library/Android/sdk

# Deque Artifactory — needed to resolve the axe-devtools-android AAR at build time
axe.username=your.email@example.com
axe.password=your_artifactory_token

# axe DevTools cloud — needed at test runtime for authentication
axe.apiKey=your-api-key-here
axe.projectId=your-project-id-here
```

- `axe.username` / `axe.password` → used in `settings.gradle.kts` to authenticate against `https://agora.dequecloud.com:443/artifactory/libs-release`
- `axe.apiKey` / `axe.projectId` → injected as `BuildConfig.AXE_DEVTOOLS_APIKEY` and `BuildConfig.AXE_DEVTOOLS_PROJECT_ID` via `app/build.gradle.kts` (debug build type only)
- Obtain all four values from [axe.deque.com](https://axe.deque.com) → Account → API Access

**If any of these are missing the symptoms are:**
- Missing `axe.username`/`axe.password` → Gradle sync/build fails, cannot resolve axe AAR
- Missing `axe.apiKey`/`axe.projectId` → Build succeeds, but `axe.isUserAuthenticated()` returns `false` at runtime, and every `axe.scan()` call returns `null`, causing `AssertionError: Scan returned null for <Screen>`

## Accessibility Test

Single test file: `app/src/androidTest/java/com/embel/shop/AxeAccessibilityTest.kt`

### Correct setup order (important)

`setInstrumentation` must be called **before** `startSession`. Both belong in `@Before`, not in `init {}`:

```kotlin
@Before
fun setup() {
    axe.setInstrumentation(InstrumentationRegistry.getInstrumentation())
    axe.startSession(
        apiKey = BuildConfig.AXE_DEVTOOLS_APIKEY,
        projectId = BuildConfig.AXE_DEVTOOLS_PROJECT_ID
    )
}
```

Putting `startSession` in the `init {}` block runs it before instrumentation is set and before the activity launches, causing authentication to fail (especially for the first test that runs alphabetically).

### Test methods and navigation

JUnit 4 runs tests alphabetically. Tests navigate using bottom nav bar labels (`onNodeWithText`) or content descriptions (`onNodeWithContentDescription`):

| Test method | Screen | Navigation selector |
|---|---|---|
| `cartScreen_accessibilityScan` | Cart | `onNodeWithText("Cart")` |
| `homeScreen_accessibilityScan` | Home | none (default screen) |
| `loginScreen_accessibilityScan` | Login | `onNodeWithContentDescription("Account")` |
| `productDetailScreen_accessibilityScan` | Product Detail | `onNodeWithText("Shop")` → `onNodeWithText("End Grain Cutting Board")` |
| `shopScreen_accessibilityScan` | Shop | `onNodeWithText("Shop")` |

Animations are disabled in test builds (`animationsDisabled = true` in `app/build.gradle.kts` `testOptions`).

### Diagnosing scan() returning null

1. Check logcat for `AxeA11yTest` tag — look for `Authenticated: false`
2. If false → credentials missing or wrong in `local.properties`
3. Verify `BuildConfig.AXE_DEVTOOLS_APIKEY` is non-empty (check `app/build/generated/source/buildConfig/debug/`)
4. Confirm `setInstrumentation` is called before `startSession` in `@Before`
